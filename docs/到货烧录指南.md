# 到货烧录指南（ESP32-S3-Touch-AMOLED-2.16）

> 目标：板子到手后，从零到屏幕上跑出雷达页，全程约 30~60 分钟（大头是首次下载工具链）。

---

## 一、开箱先确认

盒子里应该有：

- ESP32-S3-Touch-AMOLED-2.16 主板 ×1（屏幕已贴好，**不用自己装屏**）
- 2.16 寸 AMOLED 480×480 / 电容触摸
- 板载：双麦克风、功放 + 喇叭、AXP2101 电源管理、QMI8658 六轴、PCF85063 RTC、TF 卡槽

**需要你自备**：一根 **USB-C 数据线**（能传数据的，不是纯充电线）。

**电池（可选）**：MX1.25 2PIN 接口，3.7V 锂电。装之前一定要垫上包装里的 **PC 绝缘片**，把电池和 PCB 隔开。

> 板子只有一个 USB-C 口，直连 ESP32-S3 的**原生 USB**（GPIO19/20），不是 CH340/CH343。Windows 10/11 **免驱**，插上就是「USB 串行设备 (COMx)」。

---

## 二、电脑装环境

### Windows

1. 装 Python 3.10 或更高：<https://www.python.org/downloads/>
   安装时**务必勾选 `Add python.exe to PATH`**。
2. 打开 PowerShell，装 PlatformIO：

```powershell
pip install -U platformio
```

3. 验证：

```powershell
pio --version
```

> 更省事的替代：装 VS Code + 扩展 `PlatformIO IDE`，之后可以点按钮编译/上传。命令行方式与它完全等价。

### macOS

```bash
brew install python3
pip3 install -U platformio
```

---

## 三、拿到工程

在 WorkBuddy 里下载 `esp32_radar_fw.zip`，解压到任意目录，例如：

```
D:\esp32_radar_fw
```

进入该目录（后面的命令都在这个目录里执行）：

```powershell
cd D:\esp32_radar_fw
```

目录里应该能看到 `platformio.ini`、`src\`、`device\`、`preview\`。

> 只想在电脑上先看界面、不接板子？看 [本地打开工程.md](本地打开工程.md) 第三节（装 CMake + SDL2，跑模拟器）。

---

## 四、拉微雪官方库（屏幕 + 触摸驱动）

```bash
git clone --depth 1 https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.16 vendor/waveshare-demo
```

这个仓库里带出厂固件，体积偏大，网络慢就多等一会。工程只用到其中的：

```
vendor/waveshare-demo/examples/arduino/libraries/
    ├── GFX_Library_for_Arduino   （CO5300 屏驱动）
    ├── SensorLib                 （CST9220 触摸）
    └── Mylibrary/pin_config.h    （引脚定义）
```

`platformio.ini` 里已经把 `lib_extra_dirs` 指向这个目录，**不用手动拷文件**。

---

## 五、烧录

1. 用 USB-C 数据线把板子接到电脑。
2. 板子上电后屏幕会亮（出厂固件是 Brookesia 桌面）。若没反应，按一下 **PWR** 键。
3. 执行：

```bash
pio run -t upload
```

首次运行会自动下载 ESP32 工具链（几百 MB），可能 5~15 分钟；之后每次编译只要 1~2 分钟。

看到下面这类输出就成功了：

```
Writing at 0x000f0000... (100 %)
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
========================= [SUCCESS] Took 42.31 seconds =========================
```

4. 烧完**拔掉 USB 再插回**（或按一下 PWR），程序才会跑。

### 如果卡在 `Connecting...` 或找不到端口

这是没进下载模式。按官方做法：

1. **按住 BOOT 键不放**
2. 把 USB 线插上电脑
3. 松开 BOOT
4. 重新执行 `pio run -t upload`

也可以先 `pio device list` 看有没有识别到串口。

## 六、看日志

```bash
pio device monitor
```

波特率 115200。正常会看到：

```
=== ESP32 塔台雷达 · 启动 ===
[app] 进入配网模式 HGH-RADAR / 192.168.4.1
```

按 `Ctrl + C` 退出。

## 七、首次配网（不用电脑）

第一次开机没有 WiFi 凭据，板子自动开热点：

1. 手机连 WiFi：**HGH-RADAR**（无密码）
2. 浏览器打开 <http://192.168.4.1>
3. 填：
   - WiFi 名称 / 密码
   - 和风天气 Key + 你的专属 API Host（控制台里那个 `xxx.qweatherapi.com`）
   - 纬度 / 经度（雷达中心，也是天气位置）
   - 雷达量程（60 / 120 / 200 NM）
   - 航班数据源（ADS-B 公益源 / OpenSky / 本地接收机 / 演示）
4. 点保存，板子自动重启并连 WiFi。

> 手机浏览器在 `http://192.168.4.1` 这种非 HTTPS 页面上，定位接口常被拦。
> 「使用当前位置」按钮只是尽力尝试，失败就**手动填经纬度**。
> 表单里空着的项不会覆盖旧值，只改一项也能安全提交。

## 八、常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 屏幕全黑，串口有日志 | 亮度太低或屏幕未初始化 | 串口看 `[port] gfx begin FAILED`；先用官方示例 `05_LVGL_Widgets` 验证硬件 |
| 画面上下颠倒 / 镜像 | CO5300 扫描方向 | 改 `src/port/port_esp32.cpp` 第 72 行 `writeC8D8(0x36, 0xA0)`，试 `0x00` / `0xC0` / `0x60` |
| 触摸点不准 / 反了 | 坐标变换 | 改 `setSwapXY` / `setMirrorXY` 两个开关 |
| 串口打印 `touch offline` | 触摸没起来 | 检查排线；确认 `TP_RST=40`、`TP_INT=11` |
| 编译报 `Sketch too big` / 分区溢出 | 固件超过 3MB | 见下方「分区表」 |
| `pio` 找不到端口 | 数据线是充电线 / 没进下载模式 | 换线；按住 BOOT 插线 |
| 屏幕亮度刺眼 | 默认 180/255 | 改 `setBrightness()`，或后续接配网页 |

### 分区表（只在固件超 3MB 时用）

`platformio.ini` 现在用 `default_16MB.csv`（app 分区 3MB）。中文字库 447KB + LVGL 9，正常在 2.5MB 左右，够用。若真超了，新建 `partitions_app8.csv`：

```
# Name,   Type, SubType, Offset,   Size,     Flags
nvs,      data, nvs,     0x9000,   0x5000,
otadata,  data, ota,     0xe000,   0x2000,
app0,     app,  ota_0,   0x10000,  0xC00000,
```

并把 `platformio.ini` 里改成：

```ini
board_build.partitions = partitions_app8.csv
```

代价是没有 OTA 备份分区（只能插线烧）。

## 九、以后改代码怎么重新烧

改完直接再来一次：

```bash
pio run -t upload
```

- Flash 可反复烧（寿命约 10 万次），不用怕。
- **配网信息存在 NVS 里，重新烧不会丢**。只要别在烧录工具里勾 `Erase All Flash`。
- 想免插线更新，可以在 `main_esp32.cpp` 里加 ArduinoOTA，属于后续增强项。

---

## 十、这一步之后的待办

硬件跑通后，真正需要现场验证的只有三件事：

1. `pio run` 能否链接通过（`port_esp32.cpp` 调用的 GFX/SensorLib API 是否与 vendor 版本一致）
2. 屏幕方向和触摸坐标是否对齐
3. 雷达页在真机上能否跑到 20fps（PSRAM 带宽）

其余 UI、数据、配网逻辑已经在 PC 模拟器里跑通，不依赖硬件。
