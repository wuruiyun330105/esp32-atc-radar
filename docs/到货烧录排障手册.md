# 到货烧录排障手册

> 配套 `docs/到货烧录指南.md` 使用：那份讲"怎么烧"，这份讲**"烧完怎么逐层验证 + 出了问题怎么定位修"**。
> 固件已内置到货自检日志，烧完打开串口（`pio device monitor`，115200）照着本手册逐层核对即可。

---

## 〇、烧录前三查（90% 的"烧不进去"在这三步）

| 查什么 | 命令 / 动作 | 通过标准 |
|---|---|---|
| ① 工具链 | `pip install -U platformio && pio --version` | 能打印版本号 |
| ② 微雪库 | 看 `vendor/waveshare-demo/examples/arduino/libraries/` 下有无 `Mylibrary/pin_config.h` | 文件存在 |
| ③ 数据线 | USB-C **数据线**（很多充电线无数据脚），插板子 USB 口 | `pio device list` 能看到串口 |

编译验证：`pio run`（只编译不上传）。首次编译约 3~8 分钟，产出 `.pio/build/waveshare_amoled_216/firmware.bin` 即通过。

## 一、第一次烧录

```bash
pio run -t upload        # 卡在 Connecting... 就按住 BOOT 再插线，松手继续
pio device monitor       # 看日志，波特率 115200
```

## 二、分层验证流程（按顺序，每层过了再下一层）

### L0 上电串口 —— 先看日志不看屏

正常输出顺序（约 2 秒内）：

```
[port] PSRAM: OK (8388608 bytes)
[port] 内部剩余堆: 2xxxxx bytes
[port] CO5300 OK（480x480 QSPI）
[port] CST92xx OK（5 点，addr=0x5A）
[port] 硬件自检完成
[app] 配置: ssid="xxx" src=1 range=120NM lat=30.23 lon=120.43
```

- **PSRAM 显示"未启用"** → `platformio.ini` 的 `qio_opi` / `-DBOARD_HAS_PSRAM` 被改动过，恢复即可。
- 后面任何一行 `!!` 开头 → 对应层有问题，跳到第四节症状表。

### L1 屏幕点亮

自检通过后屏会黑一下（fillScreen），随后进入雷达页（无 WiFi 凭据则先见配网页提示日志）。

- 屏不亮但日志报 `CO5300 OK` → 看第四节"屏不亮"。
- 屏亮但**上下颠倒 / 左右镜像** → 改 `port_esp32.cpp` 里 `writeC8D8(0x36, 0xA0)` 的第二个字节：

| 想要的方向 | 0x36 值 |
|---|---|
| 当前设定（MY+MX，180°） | `0xA0` |
| 无旋转 | `0x00` |
| 水平镜像 | `0x40` |
| 垂直镜像 | `0x80` |

480×480 方屏旋转 90° 无意义，只需在镜像组合里试。

### L2 触摸

手指在屏上划动 / 点击目标弹详情卡。**触摸方向偏了**改 `port_esp32.cpp` 这两行组合（8 种组合逐个试，10 次以内必中）：

```cpp
s_touch.setSwapXY(true);          // true/false
s_touch.setMirrorXY(true, false); // (true/false, true/false)
```

经验法则：先 `setSwapXY` 对调 X/Y 让"上下能对上"，再单独翻转 `setMirrorXY` 两个参数让"左右对上"。

### L3 WiFi（有配置时）

```
[net] WiFi 连接尝试 #1 ("你的SSID")...
[net] WiFi 已连接 IP=192.168.x.x RSSI=-5x dBm
```

- 一直重连失败 → 确认路由是 **2.4G**（ESP32 不支持 5G 频段）、密码正确、信号 RSSI > -75。
- 想重配网：手机连热点 `HGH-RADAR` → `http://192.168.4.1`。

### L4 数据

```
[net] 航班 xx 架（源=1，外推接管）
[net] 天气 12°C 晴（15min 后再刷）
[radar] 实测 19.3 fps
```

- 航班长期 0 架：国内公益源覆盖稀是**预期行为**（README 有说明），换 OpenSky 或本地 dump1090；日志左下角仍显示 `SIM DEMO` 属正常回退，画面不空。
- 航班动态页"暂无航班/等待数据"：先确认配网页填了**飞常准 MCP Key**（sk-user- 开头，自行申请）；串口看 `[net] !! 航班动态拉取失败` = Key 无效或额度耗尽（cmcp.variflight.com 控制台查）；`[net] 航班动态 0 条` = 该机场今日航班已全部起飞（深夜正常，会自动改显最近起飞的）。
- 飞常准按调用计费（10 分钟一刷），额度紧张时可在 main_esp32.cpp 把 10min 改大（如 30min）。
- **源被拒会自动跳过**：adsb.lol 被 Cloudflare 拦 / airplanes.live 403 时，该源暂停 1 小时不再请求（不刷屏、不卡轮询）；adsb.fi 通了就完全无感。给 airplanes.live 发申请邮件（模板见 README 第三节），通过后自动恢复，无需改代码。
- **OpenSky 429 不用管**：配额耗尽自动冷却 15 分钟、轮询间隔自动放宽到 ~20 分钟，恢复后自动收回；画面保持旧数据继续死推算，不会"冻死"。
- `airplanes.live 403`：该源 2026 年起需邮件申请，前面 adsb.fi / adsb.lol 通了就不受影响。

### L5 手感

- 帧率日志低于 12 fps → 见第四节"卡顿"。
- 手势切页时误弹详情卡 → `app_pages.c` 的 `gesture_cb` 里加抑制标志（LVGL9 GESTURE 与 CLICKED 同发的兼容处理，出现了再修，10 行以内）。

## 三、症状速查表

| 症状 | 首查位置 | 修法 |
|---|---|---|
| 串口完全无输出 | 线/端口 | 换数据线；`ARDUINO_USB_CDC_ON_BOOT=1` 保持；选对 COM 口 |
| 编译报 `pin_config.h: No such file` | vendor 库没拉 | `git clone --depth 1 https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.16 vendor/waveshare-demo` |
| 编译报 touch/gfx 头文件找不到 | vendor 库版本 | `lib_extra_dirs` 路径对齐官方仓库结构 |
| `PSRAM: 未启用` | platformio.ini | `qio_opi` + `-DBOARD_HAS_PSRAM` + `16MB` 三项齐 |
| 屏不亮 + `gfx begin FAILED` | 供电/排线 | 排线重插；开机日志看 `[port] AXP2101 OK/!! PMU 不在线`（已内置官方同款 PMU 自检，不动供电轨） |
| 屏亮但全白/雪花 | 方向寄存器 | 0x36 试 0x00/0x40/0x80/0xC0 |
| 触摸无效 + `touch offline` | I2C | 确认 PMU 给触摸供电；IIC_SDA=15 / IIC_SCL=14 |
| 触摸方向偏 | port_esp32.cpp | setSwapXY/setMirrorXY 8 组合（见 L2） |
| WiFi 循环重连 | 路由 | 2.4G、密码、RSSI；仍不行 Erase Flash 重配网 |
| 航班永远 0 架 | 数据源 | 配网页换源；最佳方案本地 dump1090（30 元 RTL-SDR） |
| 卡顿 < 12fps | 帧率日志 | `port_esp32.cpp` 的 `BUF_LINES` 60→30（代价是刷新分区更多） |
| 想彻底重来 | 全擦 | `pio run -t erase` 后重烧，重新配网（配网信息会丢，属预期） |

## 四、固件侧已内置的"到货保险"

本轮评审修复后已具备（无需再改）：

- WiFi 断线**自动重连**（30s 退避，永不放弃，路由重启后自愈）
- 开机**立即**拉航班/天气（不再等 15 分钟假数据）
- 航班数据跨核交接有序号锁，不会读到半份数据
- **数据源健康记忆**：403 源暂停 1h、429/限流文本暂停 5min、成功即恢复；adsb.lol 已改官方 `/v2/point` 端点
- **OpenSky 自适应**：5min/次轮询 + 429 自动冷却 15min（间隔放宽到 ~20min），匿名配额 400/天全天可跑
- 屏/触摸/PSRAM/配置四项开机自检日志 + 每 10s 实测帧率日志
- adsb.lol 已改为官方 `/v2/point` 端点形状

## 附：板载音频硬件档案（原版仓库 waveshareteam/ESP32-S3-Touch-AMOLED-2.16 实证）

这块板自带完整音频链路（将来想加"塔台对话"播报时用）：

- **编解码器**：ES8311（DAC 出喇叭 + ADC 收麦），功放使能脚 `PA=GPIO46`（输出 HIGH 开功放）
- **麦克风 ADC**：ES7210（4 通道，回声消除演示用它）
- **I2S 引脚**（pin_config.h 已定义）：BCLK=9 / LRCK=45 / DIN=10 / MCLK=42 / DOUT=8
- **官方示例**：`07_ES8311.ino`（I2S 16kHz 立体声 + es8311.c 驱动，麦克风→喇叭实时回声）；`06_ES7210.ino`（录音）
- **接到本工程的路径**（将来做 ATC 音频页）：WiFi 拉 LiveATC/HLS 音频流 → 解码（MP3/AAC，可用 ESP_ADPCM/libhelix）→ PCM → I2S → ES8311 → PA。I2S 与触摸共用总线无冲突（不同引脚），与 LVGL 主循环需分任务跑
